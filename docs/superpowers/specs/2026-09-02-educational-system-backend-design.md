# Образовательная система — backend MVP

## Цель

Перевести текущий frontend-прототип стимулирующих выплат с `localStorage` на локально запускаемый backend без Docker. Backend должен обеспечить авторизацию, разграничение по школе, настраиваемые критерии, заявки, документы, Excel-выгрузку, уведомления и просмотр профиля.

## Ограничения MVP

- Запуск без Docker: Node.js, Prisma и SQLite-файл `data/dev.db`.
- Один завуч на школу; роли `TEACHER` и `DEPUTY`.
- История заявок и документы хранятся бессрочно.
- Документы загружаются вручную; внешних интеграций нет.
- Одна заявка учителя на отчётный период. Отклонённую заявку можно редактировать и отправить повторно.
- Один backend-процесс и локальное файловое хранилище `storage/` для первого MVP.

## Архитектура

Репозиторий сохраняет текущий статический UI и получает отдельный backend в `server/`.

- HTTP API: NestJS, REST, JSON.
- ORM и миграции: Prisma.
- База: SQLite (`data/dev.db`).
- Авторизация: короткоживущий JWT access token и refresh token, сохранённый в БД.
- Пароли: Argon2id или bcrypt с безопасной стоимостью.
- Файлы: UUID-имя в `storage/`, метаданные и владелец в БД.
- Excel: `exceljs` или совместимая библиотека, формирование файла на сервере.
- Валидация: DTO с `class-validator`; все проверки повторяются на сервере.

Слои backend: `modules/*` (контроллеры и use cases), `domain` (правила расчёта и статусы), `prisma` (доступ к данным), `common` (auth guards, ошибки, аудит).

## Модель данных

- `School`: идентификатор, название, активность.
- `User`: идентификатор, ФИО, email, hash пароля, роль, `schoolId`, должность, даты создания/обновления.
- `RefreshToken`: хеш токена, пользователь, срок действия, отзыв.
- `Period`: отчётный период, дата начала/окончания приёма, активность.
- `Criterion`: название, категория, тип (`FIXED`, `QUALITY`, `OLYMPIAD`, `CUSTOM`), лимит, активность, версия.
- `CriterionField`: поле критерия, тип (`TEXT`, `NUMBER`, `SELECT`, `DATE`, `FILE`), обязательность, порядок, настройки выбора и диапазонов.
- `CriterionScale`: диапазон/условие и денежное значение для качества, олимпиады или пользовательского критерия.
- `Application`: учитель, школа, период, статус (`DRAFT`, `REVIEW`, `APPROVED`, `REJECTED`), итог, комментарий, даты отправки/решения.
- `ApplicationItem`: заявленный критерий, снимок версии критерия, рассчитанная сумма и значения динамических полей.
- `OlympiadEntry`: уровень, степень диплома, ученик, олимпиада и сумма внутри application item.
- `EvidenceFile`: имя, MIME, размер, путь, заявка/элемент, загрузивший пользователь.
- `Notification`: пользователь, тип, заголовок, текст, ссылка, прочитано/дата.
- `AuditLog`: пользователь, школа, действие, сущность, идентификатор, JSON-детали, дата.

Уникальное ограничение: `(teacherId, periodId)` для заявки. Все запросы завуча дополнительно фильтруются по `schoolId` из JWT, а не по параметру клиента.

## API-контракты

### Авторизация и профиль

- `POST /api/auth/register` — создать пользователя с привязкой к существующей школе.
- `POST /api/auth/login` — вернуть access/refresh токены.
- `POST /api/auth/refresh` — обновить access token.
- `POST /api/auth/logout` — отозвать refresh token.
- `GET /api/profile` — текущий профиль и школа.
- `PATCH /api/profile` — изменить разрешённые поля профиля.

Регистрация завуча требует серверной проверки, что в школе ещё нет завуча. Пароль и токены никогда не возвращаются клиенту.

### Критерии

- `GET /api/criteria` — активные критерии для учителя или полный список для завуча своей школы.
- `POST /api/criteria` — создать критерий (только `DEPUTY`).
- `PATCH /api/criteria/:id` — изменить название, поля, лимит и шкалы (только `DEPUTY`).
- `DELETE /api/criteria/:id` — мягко отключить критерий, если он уже использован.

Изменение критерия создаёт новую версию; уже отправленная заявка хранит снимок настроек и суммы.

### Заявки и проверка

- `GET /api/applications` — собственные заявки учителя или заявки своей школы для завуча.
- `POST /api/applications` — создать единственный черновик периода.
- `GET /api/applications/:id` — получить заявку после проверки доступа.
- `PATCH /api/applications/:id` — редактировать только черновик или отклонённую заявку.
- `POST /api/applications/:id/submit` — серверная валидация и перевод в `REVIEW`.
- `GET /api/reviews` — очередь заявок `REVIEW` своей школы.
- `POST /api/reviews/:id/approve` — утвердить заявку.
- `POST /api/reviews/:id/reject` — отклонить с обязательным комментарием.

Все переходы статусов атомарны и проверяют текущий статус. Повторная отправка отклонённой заявки очищает старое решение, сохраняя аудит.

### Файлы, отчёты, уведомления

- `POST /api/files` — multipart-загрузка разрешённого типа и размера, с привязкой к элементу заявки.
- `GET /api/files/:id` — скачивание только участником заявки или завучем своей школы.
- `GET /api/reports/:periodId/export.xlsx` — Excel по утверждённым выплатам своей школы.
- `GET /api/notifications` — уведомления текущего пользователя.
- `POST /api/notifications/:id/read` — отметить уведомление прочитанным.

Для загрузок применяются allowlist MIME/расширений, лимит размера, UUID-имя и запрет исполнения файлов. Excel содержит листы заявок, критериев и итогов.

## Разрешения

Учитель может читать/изменять только свой профиль и свои заявки, выбирать критерии, заполнять динамические поля и загружать подтверждения. Учитель не может менять денежные значения, шкалы и чужие заявки.

Завуч может читать заявки, пользователей и отчёты только своей школы, принимать решения, создавать и настраивать критерии. Доступ к другой школе невозможен даже при подмене URL или ID.

## Клиентский переход

Текущий UI сохраняется визуально. Добавляется `src/api.js` с fetch-клиентом и обработкой 401/ошибок. Состояния авторизации, критериев, заявок, уведомлений и профиля загружаются из API; `localStorage` используется только для сохранения access token в пределах MVP или полностью убирается после завершения миграции.

## Ошибки и аудит

API возвращает единый формат ошибки `{ code, message, details? }`. Ошибки валидации привязаны к полям формы. Записываются регистрации, входы, изменения критериев, загрузки, отправки, решения и выгрузки отчётов. В аудит не попадают пароли и содержимое токенов.

## Тестирование и этапы

1. Prisma schema, миграции, seed, auth и school-scope.
2. Критерии и версии настроек.
3. Заявки, расчёт, валидация и review workflow.
4. Файлы, уведомления и Excel.
5. Подключение текущего UI к API.

Тесты запускаются после каждого полноценного этапа, а не после каждого косметического изменения: unit-тесты доменных правил, integration-тесты API с SQLite и один smoke-сценарий авторизации/заявки/выгрузки.

## Запуск

```bash
npm install
npm run db:migrate
npm run seed
npm run dev
```

Frontend и API работают локально без Docker; точные порты и proxy будут зафиксированы в implementation-плане.
