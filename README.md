# Образовательная система — MVP стимулирующих выплат

UI и локальный backend MVP по ТЗ. Backend запускается без Docker на NestJS + Prisma + SQLite.

## Запуск в Docker (production)

```bash
cp .env.example .env   # задайте JWT-секреты и (опционально) Brevo
docker compose up -d --build
```

Фронтенд: `http://localhost`, API за тем же доменом (`/api`). Подробная поэтапная инструкция для Ubuntu — [DEPLOY.md](DEPLOY.md).

## Запуск без Docker (локальная разработка)

```bash
python3 -m http.server 4173
```

Откройте `http://localhost:4173`. При первом открытии система показывает форму входа. Новый сотрудник выбирает роль и школу при регистрации; после входа доступен только контур своей школы.

### Backend без Docker

Требуется Node.js 20+.

```bash
npm install
npm run server:install
cp server/.env.example server/.env
npm run server:dev
```

При первом запуске сервер сам создаёт базу (`data/dev.db`), применяет миграции и сиды. Дополнительно доступно: `npm run db:migrate`, `npm run seed`.

API: `http://localhost:3001`.

Проверка backend без Docker: `npm run server:test` (unit-тесты + e2e smoke-сценарий). Для production-подобного локального запуска используйте `npm run server:start`.

Для проверки после seed доступны аккаунты: `deputy@school101.local` / `demo1234` и `teacher@school101.local` / `demo1234`.

## Что реализовано

- роли учителя и единственного завуча;
- обязательная привязка профиля к школе; завуч видит только свой schoolId-контур;
- управление отчётными периодами: завуч открывает новый период (предыдущий закрывается автоматически) и закрывает приём заявок; учитель видит список периодов и свою заявку в каждом;
- одна заявка на отчётный период;
- выбор критериев с фиксированной суммой выплаты; завуч может изменить сумму в диапазоне `0…maxAmount`, учитель только видит назначенное значение;
- специальный критерий «Качество обученности»: учитель вводит процент `0…100`, выплата выбирается по шкалам `0–50%`, `>50–75%`, `>75–90%`; выше 90% выплата не начисляется;
- специальный критерий олимпиад: уровень, степень диплома, ФИО ученика и название олимпиады; можно добавить несколько учеников, начисление идёт только по полностью заполненным строкам;
- ручная загрузка подтверждающего файла;
- черновик → проверка → утверждение/отклонение с комментарием;
- повторная работа с отклонённой заявкой;
- очередь проверки, критерии, сотрудники и реестр отчёта;
- Excel-выгрузка реестра утверждённых выплат: суммы по фактически утверждённым заявкам, а не лимитам критериев;
- локальное сохранение состояния и журнала действий в `localStorage` (fallback при недоступном API).

## Данные

SQLite хранится в `data/dev.db`, загруженные подтверждения — в `storage/`. История заявок и документы не удаляются автоматически.
